# 0001. 직렬 gzip 하한을 수용하고 최적화 축을 총 CPU로 설정

- 상태: 승인 (2026-08-07)

## 맥락

전체 파이프라인에서 유일한 직렬 구간은 단일 스트림 gzip 해제다
(표준 샘플 기준 M4 ~24s, Xeon ~44s). 코어가 충분한 환경에서는 이것이
wall time의 하한이 되며, 코드로는 깰 수 없다 — 단일 스트림 gzip은
알고리즘 특성상 병렬 해제가 불가능하다.

하한을 깨는 유일한 방법은 입력 포맷 변경(zstd, 블록 단위 gzip)이지만,
`A.tar.gz`는 외부 생산자가 만들며 포맷 협상이 불가능함을 확인했다.

## 결정

- 다코어 환경의 wall 하한(직렬 gzip 해제 시간)은 물리 한계로 수용한다.
- 성능 최적화의 축은 **총 CPU 절감**으로 설정한다. 저코어 환경에서는
  wall ≈ 총 CPU ÷ 코어 수이므로 wall에 1:1로 반영되고, 다코어 환경에서도
  손해가 없다.
- 판정 지표는 wall이 아니라 **user CPU**(환경 독립적 대리 지표)로 한다.

## 결과

- 병렬 해제를 시도하는 재설계는 하지 않는다. 미래에 입력 포맷이
  협상 가능해지면 이 결정은 재검토한다.
- 실행 환경이 1코어~수십 코어 스펙트럼이므로, 특정 코어 수를 가정한
  튜닝 대신 코어 수에 무관하게 이득인 변경만 채택한다.
